# Miro System Map Content

## Purpose

This board should help explain the platform fast to:
- Logan
- collaborators
- prospects
- future customers

The goal is to make the system feel understandable, useful, and sellable in a few minutes.

## Board title

**XactIQ Memory + Mission Control Platform**

## Board framing sentence

A system for turning scattered business context, documents, tasks, and agent activity into a searchable memory layer plus an operational control layer.

## Main board layout

Use six major zones from left to right.

### 1. Inputs and Sources

Cards:
- Google Workspace
- Gmail
- Google Drive
- Calendar
- Local memory files
- Discord
- OpenClaw sessions
- Documents
- CRM / business records (future)
- Microsoft 365 (experimental)

Label for zone:
**Where information comes from**

### 2. Canonical Memory Layer

Cards:
- Workspaces
- Memory Records
- Entities
- Relationships
- Sources
- Connector Snapshots
- Sync Jobs
- Audit Events
- Provenance

Label for zone:
**Shared source of truth**

Key note:
Both Memory Hub and Mission Control should use this layer, not each other directly.

### 3. Memory Hub

Cards:
- Graph / globe view
- Search
- Add Memory
- Source Explorer
- Detail Drawer
- Provenance view
- Connected docs and email retrieval

Label for zone:
**Human-facing memory product**

Key value note:
Find what matters. Remember what matters. Open the real source.

### 4. Mission Control

Cards:
- Connector status
- Sync jobs
- Audit log
- Agent monitoring
- Workflow overview
- Alerts and failures
- Governance / approvals

Label for zone:
**Operational control layer**

Key value note:
Know what ran, what failed, what changed, and what needs attention.

### 5. Miro Mirror

Cards:
- System map
- Strategic memory map
- Workflow map
- Monetization map
- Customer demo board

Label for zone:
**Visual mirror and planning layer**

Key note:
Miro is not the source of truth. It mirrors and explains the system.

### 6. Business Outcomes

Cards:
- Faster retrieval
- Better agent context
- Less duplicated work
- More reliable operations
- Better client delivery
- Sellable SaaS product
- Sellable implementation service
- Better security visibility

Label for zone:
**Why this matters commercially**

## Recommended connector lines

Draw arrows:
- Inputs and Sources -> Canonical Memory Layer
- Canonical Memory Layer -> Memory Hub
- Canonical Memory Layer -> Mission Control
- Canonical Memory Layer -> Miro Mirror
- Memory Hub -> Business Outcomes
- Mission Control -> Business Outcomes
- iBuilders Lab -> Memory Hub
- iBuilders Lab -> Mission Control
- iBuilders Lab -> Business Outcomes

## iBuilders Lab placement

Place iBuilders Lab above or below the main flow as a builder/implementation layer.

Cards:
- Workflow implementation
- Custom setup
- Vertical solutions
- Client onboarding
- Done-for-you integration

Label:
**Implementation and services layer**

## Callout notes to place on board

### Callout 1
**Memory Hub sells the value of memory.**
People can understand this product quickly because it helps them find context, files, and decisions.

### Callout 2
**Mission Control sells the value of oversight.**
Operators can see jobs, connector health, failures, and system state.

### Callout 3
**Miro sells the vision.**
It helps people understand the system without turning it into the backend.

### Callout 4
**iBuilders Lab sells implementation.**
This is the services bridge that can generate near-term revenue while the platform matures.

## Suggested board close

Put a bottom-right note:

**End state:** a memory product, an operations product, and an implementation business, all sharing one trusted backbone.
