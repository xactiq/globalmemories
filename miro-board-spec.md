# Miro Board Spec

## Board 1: Platform System Map

Purpose:
- explain the full platform to yourself, collaborators, or customers

Main nodes:
- Memory Hub
- Mission Control
- iBuilders Lab
- Shared Canonical Memory Layer
- Connectors
- OpenClaw
- Google Workspace
- Microsoft Graph
- Miro Mirror

## Board 2: Strategic Memory Map

Purpose:
- visualize important people, projects, systems, documents, and decisions

Main regions:
- People
- Projects
- Systems
- Documents
- Decisions
- Relationships

Rules:
- each item should link back to canonical source records when possible
- board items should be summaries, not raw data dumps

## Board 3: Monetization and Packaging

Purpose:
- keep pricing, packaging, and upgrade paths visible

Main regions:
- Memory Hub tiers
- Mission Control tiers
- iBuilders Lab services
- target customer segments
- upsell paths
- enterprise options

## Sync guidance

Preferred sync direction:
- canonical layer -> Miro mirror

Required qualities:
- linked references back to real records
- no secrets
- no raw token state
- no canonical-only data living solely in Miro
